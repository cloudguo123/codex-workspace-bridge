# 一次主开发机迁移的复盘

案例目标：桌面 Mac 作为主开发机，笔记本通过远程 App 输入、交互与演示；内置 SSD 放活跃工程，外置 8TB 机械盘扩展资料容量。期间仍有项目开发，网络位置也发生变化。

## 按实际结果回看

1. **先救完整性。** 发现 40 个修改/未跟踪工作区和 26 个尚无首次提交的 Git 目录。远程 Git 不会保存未提交内容；工作树也不是彼此独立仓库。先保留原目录、对象库和全部工作树，再谈整理。
2. **容量分层不是备份。** 外置盘从空盘 exFAT 改 APFS 经过用户单独确认，启用所有权；没有因迁移需要默认格式化。工作资料放外置盘后，其同盘副本不能算独立故障域。
3. **建立传输通道。** SSH 先解决服务、首次主机指纹与专用密钥。DHCP IP 改变导致来源限制失配；最终离开局域网后改用已有远程工具传小型恢复包。没有用开放公网 SSH 替代原有安全边界。
4. **工程与运行分开。** 项目文件、Git 状态、语言环境、原生编译、数据库逻辑恢复、浏览器/API 测试分别留证。复制完成的工程不一定能运行，项目注册也不等于 App 界面可见。
5. **动态项目必须做增量。** 后续检查覆盖 34 个项目、80 个目录/工作树；265 个普通差异候选哈希相同，67 组重点 Git 对照一致。候选哈希检查不能夸成所有数百万文件重新哈希。
6. **聊天不是项目目录里的文件。** 源机普通聊天仍在，目标迁入项目“暂无聊天”。经历官方交接试点、草稿保护、隔离副本演练后，按冷窗口将 123 条原普通聊天恢复到 33 个项目；子记录、历史分段、上下文缓存与图片另行处理，目标旧记录保留。
7. **首次恢复漏掉 Goal。** 只恢复聊天索引和历史缓存，未合并独立 Goal 库，因此原聊天可见而卡片消失。这是迁移完整性清单遗漏，不应解释成“账号没同步”。后来补入 20 条 Goal，保留原 ID、目标、预算与累计量，全部暂停，原状态另存。
8. **数据成功与界面成功不同。** 补恢复脚本和双位置哈希通过后，App 缓存仍旧。经用户批准重启，实际看到 3 条原聊天的暂停 Goal 卡片；不能把抽查写成逐条界面验收。
9. **允许安全暂停。** 大型业务数据库有约 76GB 最新一致性快照，最终传输/切换未完成。用户断网时停止迁移，保留候选，按当时约定恢复源服务；没有把数据库候选升级为正式库。

## 成为工具时应保留的判断

- 先确认执行主机，再给该主机可打开的路径。不能让用户在笔记本本地文件选择器找桌面机的目录。
- “已复制”“已注册”“数据库已校验”“界面已显示”“能继续开发”“业务已切换”应是不同的状态。
- 草稿保护触发时不清空、不发送；暂停的 Goal 与定时任务不因迁移自动恢复执行。
- 同 ID 的目标新进展不是垃圾；双向冲突应停下来，不能用源机版本覆盖。
- 特定机器、磁盘 UUID、私有用户名、聊天 ID 和密钥限制不得硬编码进公共工具。
- 一次成功修复不是稳定产品保证：公开实现需要合成回归、故障注入、兼容性矩阵和真实副本验收。

本仓库只发布从案例重新实现的通用代码、合成测试和匿名经验；未复制真实业务项目、聊天、数据库、图片、授权信息或原迁移包。
